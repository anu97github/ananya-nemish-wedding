# Wedding Guestbook Google Sheets backend

The wedding website's guestbook form sends notes to the couple's Google Sheet through a Google Apps Script web app.

## Spreadsheet

The endpoint is configured in `Code.gs` to use the existing spreadsheet ID. Renaming the workbook in Google Drive does not change that ID, so the website integration continues to work after a rename.

- **Workbook:** Ananya & Nemish | Our Wedding Guestbook
- **Sheet tab:** Guestbook
- **Columns:** Date & Time, Sender Name, Message

The script appends one row per valid guest note. The timestamp is generated by Apps Script when the note is received.

## Website submission flow

1. The guest enters their name and message in the Guestbook section of the website.
2. `script.js` submits the form to the public Apps Script web-app URL configured in `rsvp-config.js`.
3. `Code.gs` validates the submission, prevents duplicate submissions, and appends the note to the **Guestbook** tab.
4. The website displays its thank-you state only after the endpoint confirms that the note was saved.

## Apps Script setup

If the endpoint ever needs to be redeployed:

1. Open the Apps Script project associated with the existing wedding guestbook spreadsheet.
2. Ensure its `Code.gs` matches this repository's `apps-script/Code.gs`.
3. Run `setupGuestbookSheet` if you need to create or reformat the Guestbook tab. It is safe to rerun; it sets the expected headers and formatting.
4. Deploy the project as a Web app, executing as the spreadsheet owner and allowing access to anyone so guests can submit without signing in.
5. If the deployment URL changes, update the endpoint in `rsvp-config.js` and deploy the website update.

## Security and operational notes

- The spreadsheet ID and Apps Script endpoint are identifiers, not credentials. Never add passwords, API keys, or access tokens to the website.
- Guests can submit notes through the endpoint but do not receive spreadsheet access.
- The endpoint applies required-field validation, length limits, a honeypot field, duplicate-submission protection, a script lock around writes, and protection against spreadsheet formula injection.
- Keep spreadsheet sharing restricted to people who should be able to read guest names and personal messages.
- Do not delete or recreate the existing **Guestbook** tab while it is connected to the website. Renaming the workbook is safe as long as its spreadsheet ID remains unchanged.
